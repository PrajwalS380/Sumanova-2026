=========================================================================================
sumanova-us-112 · Face sliders — shape, structure and feature placement, precisely mine
=========================================================================================

USER STORY
  As a SUMANOVA user, I want simple, precise sliders to make the face exactly like mine —
  wider or narrower, longer or shorter, jaw, chin, forehead and cheeks, my cheekbones and
  jaw angle, and where my eyes, nose and mouth sit — with an instant preview, easy reset and
  undo, so I can get a true likeness that a pick-a-shape avatar (Bitmoji) can't give.

WHY (what build-103 has today)
  - Only three sliders: Face size (tune.face), Eye size (tune.eyeSize), Eye spacing
    (tune.eyeGap) — Look.tune is a fixed { eyeSize, eyeGap, face } object.
  - Feature positions are hard-coded in render/Face.tsx (ex, ey, er, noseY, mouthY) and
    copied in render/Figure.tsx eyeMetrics() (for glasses) and sculpt3d/head.ts noseYFor()
    (sculpted nose). Three copies of the same maths: any new slider would drift.
  - Every slider tick calls commit() → one undo step per pixel of drag.
  - The selfie flow (selfie/analyze.ts) measures face ratio and jaw but only fills
    eyeSize / eyeGap.

1) TUNE DATA — look/config.ts
   a. Turn Look.tune into an extensible record of numbers −1 … 1 (default 0). Keep the
      three existing keys with identical meaning. New keys (this story):
        Face shape  : faceWidth, faceLength, jawWidth, chinLength, foreheadHeight,
                      cheekFull
        Structure   : browRidge, cheekbone, cheekHeight, temple, underCheek, jawAngle,
                      chinPad, chinWidth, chinCleft, smileFold   (offsets on us-111 params)
        Placement   : eyeHeight, eyeTilt, eyeSizeL/eyeSizeR asymmetry (see 1c),
                      noseHeight, noseSize, mouthHeight, mouthWidth, mouthSize
   b. Export TUNE_KEYS (the list) and a TuneKey type; normalizeLook() keeps only known
      keys, clamps to −1 … 1, fills missing with 0. Later stories append keys to the same
      list (ears, brows, nose shape, lips) — keep it one list.
   c. Asymmetry (realism, default off): eyeSizeAsym and eyeHeightAsym (−1 … 1 = left
      smaller/lower … right smaller/lower, max effect 6 %). Hidden behind a
      "Fine-tune asymmetry" toggle in the UI.
   d. RULE: with every key = 0 the face must be pixel-identical to the face before this
      story (post-us-111). Old saved avatars therefore don't change.

2) ONE LAYOUT FUNCTION — new render/faceLayout.ts
   a. `faceLayout(look, h)` returns everything that positions features:
        ex, ey, er (+ per-side er/ey for asymmetry), eyeTilt, noseY, noseScale, mouthY,
        mouthW, mouthScale.
      Move the maths from Face.tsx (ex/ey/er/noseY/mouthY), Figure.tsx eyeMetrics() and
      head.ts noseYFor() into it; all three call faceLayout (head.ts receives the needed
      numbers through the head job so the worker stays pure — add them to the 'head' Job
      and its jobKey).
   b. Glasses (Accessories.tsx) and jewellery (Jewelry.tsx: nose, brow, lip anchors) read
      the same layout so they follow eye height, nose height and mouth height.
   c. Ranges (start values; tune by screenshot, keep the face cartoon-friendly):
        faceWidth  rx × (1 ± 0.08)        faceLength ry × (1 ± 0.07)
        jawWidth   jawN − 0.12 … + 0.12   chinLength chinLow ± 0.06
        foreheadHeight  top of skull ry above the brow ± 6 % (hairline follows: groom
                        lineAt reads the head shape, check A4)
        cheekFull  h.cheeks ± 0.35
        structure keys  us-111 param + 0.5 × tune, clamped to the param's range
        eyeHeight  ey ± 0.03     eyeTilt ± 0.12 rad (adds to the variant's tilt)
        noseHeight noseY ± 0.025 noseSize scale 1 ± 0.15
        mouthHeight mouthY ± 0.03  mouthWidth w × (1 ± 0.15)  mouthSize scale 1 ± 0.12
      Guard rails: eyes never overlap the brows or the nose bridge, the nose never
      overlaps the mouth, the mouth stays above the chin — clamp in faceLayout (e.g. min
      gaps) instead of letting extreme combinations collide.
   d. Which keys need a re-sculpt: shape + structure keys change HeadShape → head job,
      hair groom, beard/hat shells (all keyed by HeadShape). Placement keys that move the
      sculpted nose (noseHeight, noseSize) → head job only. Eye/mouth placement keys →
      no worker job at all (pure render).

3) LIVE, SMOOTH EDITING — AvatarStudio.tsx
   a. While dragging: render-only keys update every frame; re-sculpt keys update a
      preview value immediately and send the job with a 150 ms debounce; the previous mesh
      stays on screen until the new one is ready (no blank / flash).
   b. Undo/redo: one history entry per drag (commit on pointer-up / change end), not per
      tick.
   c. Camera: while a depth slider is dragged (browRidge, cheekbone, chinPad, jawAngle,
      temple, underCheek, smileFold, chinLength) the stage eases to a 3/4 view, then back.
   d. Reset: double-tap a slider → 0; "Reset face" button per group (Shape / Structure /
      Placement) with undo.
   e. Grid thumbnails stay on the neutral mannequin (AvatarStudio mannequin()) — tune
      values must NOT enter thumbnail keys or the thumb cache.
